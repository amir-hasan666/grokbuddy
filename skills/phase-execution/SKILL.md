# Phase execution

Read [AGENTS.md](../../AGENTS.md) and the applicable row of [IMPLEMENTATION_PLAN.md](../../IMPLEMENTATION_PLAN.md). Establish the latest user-authorized phase; a roadmap is not an authorization. Preserve prior explicit scope and permissions.

At phase start, state the outcome, planned files, material architecture decisions, risks and external dependencies. Work through the existing phase plan directly. Reuse installed specialist skills only when the actual artifact warrants them; do not introduce a second planning lifecycle.

Before closing, run checks proportionate to the work and the phase's exit criteria. For Phase 0 use the local contract validator and skill validator; record runtime demos as not run. For implementation phases consult [TEST_MATRIX.md](../../docs/TEST_MATRIX.md), and distinguish local/mock/provider/production results.

Produce added/modified file inventory, exact commands, outcomes, unresolved items, UNVERIFIED capabilities, risks and next phase contents. Stop at the authorized boundary. If a Gate cannot pass, explain what evidence is absent and finish the unaffected authorized work; do not implement later phases as a workaround.
